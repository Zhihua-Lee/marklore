# v0.1.26 robustness, lazy math/code and CI

## Changes

- A failed recovery write (full disk, locked file, size limit) offers "quit
  anyway" instead of leaving a window that cannot close; `session.json` renames
  retry on EPERM/EBUSY/EACCES. Reproduced with a directory planted where the
  temporary session file must go.
- Folder watchers react only to the open notes they contain and are released
  when no tab uses them; the main process keeps path/encoding records instead
  of every opened document's text; temp-file cleanup cannot replace a save
  result.
- Session flushes reference unchanged drafts (`keepDraft`) instead of resending
  them; a missing reference is resent in full once.
- KaTeX and highlight.js load on first use. The startup entry chunk measured
  1,288 KB → 858 KB; bundled fonts 93 files / 2,168 KB → 53 / 1,371 KB (KaTeX
  woff2 only); `app.asar` 9.0 → 7.8 MB. V8 code cache for the `folio:` scheme;
  the window background follows the saved theme.
- `app.js` split into settings, library, split-pane, document-sync and menus
  modules (1,781 → 1,339 lines), no behaviour change intended.
- Tooling: GitHub Actions (windows-latest), shared `window.folio` test harness
  checked against `preload.cjs`, navigation specs under smooth and reduced
  motion, Prettier/EditorConfig and deterministic third-party notices.

## Automated checks

All 56 unit tests and 139 browser cases (Edge; 131 in the default project plus
8 navigation/regression cases again under reduced motion) pass. Running the
navigation specs with smooth scrolling exposed three tests that sampled scroll
positions mid-animation and one that selected text before a resize was
processed; these were fixed in the tests and stressed (42/42 with 3 workers).
Format check and Vite build pass.

## Manual/native checks

The packaged v0.1.26 build passes all nine native suites, including
the new failed-recovery-write case in the safety suite and PDF/HTML export. A
source run initially failed the hover-preview step while a real pointer crossed
the test window; the suite passed when rerun. Only synthetic notes and isolated
profiles were used.

## Limits

The first GitHub Actions run failed its format check because `.cjs` files were
checked out with CRLF on the Windows runner; `.gitattributes` now pins them to
LF. The KaTeX/highlight.js lazy load means formulas and code show as source for
a short moment after opening a note; physical mouse hardware was not exercised.
