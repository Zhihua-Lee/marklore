# v0.1.27 jumps render their destination first

## Changes

Outline and link jumps no longer show content rendering while they move. Before
scrolling, lazy formulas and table widths around the destination (one screen
above to two below) render synchronously and the target is measured against
that layout. Jumps longer than 1.5 screens cut to 0.6 screens short of the
target and glide the rest; shorter jumps glide the whole way. The instant cut's
own `scrollend` is no longer taken as landing.

Measured per animation frame in a 60-section note with 300 formulas and 60
tables: frames showing unrendered formula source during a jump went from 17–38
(v0.1.26) to 0, with 31–41 frames of glide and every heading landing at 32px;
the click itself took 1–3 ms.

## Automated checks

All 56 unit tests and 141 browser cases (Edge; default project plus the
reduced-motion project) pass. A new per-frame regression test fails on v0.1.26
in both motion projects and passes now. The code-color test now waits for the
lazily loaded highlighter (63/63 with 3 workers). Format check and Vite build
pass.

## Manual/native checks

The packaged v0.1.27 build passes all nine native suites. Only synthetic notes
and isolated profiles were used.

## Limits

Content between the start of a long jump and the cut point is skipped, not
shown. Physical mouse hardware was not exercised.
