# v0.1.29 find, clickable tasks and recent files

## Changes

- Find in the rendered note (Ctrl+F while reading; Enter/Shift+Enter, F3,
  Esc). Case-insensitive, matches across inline formatting but not across
  blocks, highlighted with the CSS Custom Highlight API; unfolds sections,
  details and collapsed code to reveal a match and refreshes after edits.
  Ctrl+F in the editor keeps CodeMirror's search panel.
- Task checkboxes in the live preview toggle their own `[ ]`/`[x]` through the
  editor (dirty, undoable), including nested, quoted and numbered items.
  Exports, hover previews and authored HTML checkboxes stay disabled.
- Recent files on the start page (with clearing) and in the Windows jump list.
  Explicit opens are recorded; session restore is not. The renderer can reopen
  only paths on the list. Test runs and isolated profiles never write the
  jump list.
- Only the zh-CN and en-US Chromium locales ship: installed size 376 → 328 MB.

## Automated checks

All 59 unit tests (including the recent-files store) and 146 browser cases
(Edge; default and reduced-motion projects) pass. New browser cases cover find
counts, cycling, unfolding and closing, CodeMirror search in the editor, all
five task-item shapes and the start-page recent list. Format check and Vite
build pass.

## Manual/native checks

The packaged v0.1.29 build passes all nine native suites; the smoke suite now
also checks that command-line and link opens are remembered across a restart,
newest first, and that `openRecent` refuses a path that is not on the list.
Only synthetic notes and isolated profiles were used.

## Limits

The jump list itself is not exercised automatically (it is disabled for
isolated profiles by design). Find does not search inside rendered formulas'
TeX source.
