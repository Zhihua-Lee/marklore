# v0.1.31 hover previews survive layout corrections

## Changes

An open hover preview no longer closes when the reader makes a small
layout-preserving scroll correction (late fonts, lazy formulas, table widths,
diagrams). It closes only when the originating link actually moved on screen.
Before, a preview could vanish while being read, and on CI a click on its close
button occasionally landed on the note underneath.

## Automated checks

All 59 unit tests and 148 browser cases (Edge; default and reduced-motion
projects) pass. A new case compensates growth above the link exactly and
checks that the preview stays open, then scrolls the link away and checks that
it closes. The hover and tab specs passed 28/28 repeated single-worker runs; a
3-worker run on a heavily loaded machine timed out while launching browsers
and was not counted. GitHub Actions passed with no retried cases.

## Manual/native checks

The packaged v0.1.31 build passes all nine native suites on the first run.
Only synthetic notes and isolated profiles were used.

## Limits

Physical mouse hardware was not exercised.
