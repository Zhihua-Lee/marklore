# v0.1.33 window controls, copy as Markdown, smoother scrolling

## Changes

- **Window.** No system title bar: the toolbar runs to the window edge and
  ends in its own compact group (full screen, minimise, maximise/restore,
  close), set apart by a rule. Full screen keeps only exit and close. Window
  state is reported on resize, since setting full screen did not emit
  `enter-full-screen` in this configuration.
- **Copy as Markdown.** Ctrl+C in the preview copies the selection's source.
  Whole inline constructs keep their markers, cut ones drop them, formulas
  and images copy whole, and a block's line prefix comes with its whole text.
  Ctrl+Shift+C copies rendered HTML plus clean text. Inline markup now
  carries source spans. Task-list text leaves no longer map four characters
  early (the task plugin trims `[ ] ` after positions were assigned).
- **Scrolling.** Ctrl+wheel zoom now comes from Electron's `zoom-changed`, so
  the page has no blocking wheel listener. While the reader is scrolled by
  wheel or keys, a transparent shield answers hover hit tests (with rendered
  KaTeX each one took ~12 ms over 14,644 positioned elements). Programmatic
  scrolls never raise the shield, pointer movement lowers it, reading anchors
  hit-test underneath it, and it is never a scroll anchor. Table layout
  measures the reading anchor only when a table actually changes.
- **README.** Install steps, feature animations and screenshots generated by
  `tools/readme-media.mjs` from `docs/sample-notebook`.

## Automated checks

All 59 unit tests and 153 browser cases (Edge; default and reduced-motion
projects) pass. New cases cover copied source, the rendered copy, the
code-block exception, window-control placement, state and actions, and the
scroll shield.

## Manual/native checks

The packaged v0.1.33 build passes all nine native suites on the first run.
The menu suite now also checks the page's own window controls and
Ctrl+wheel zoom via `zoom-changed`. Its compact-window tolerance grew from
2 to 3 logical px: the resize frame kept without a title bar rounds one
pixel wider at 350% scaling.

Real-window captures (light, dark, full screen) were inspected.

A local benchmark scrolled a 60-section note with 600 formulas, 60 tables and
60 code blocks in the packaged app, after rendering finished. Over 40 wheel
notches:

| Build   | Dropped frames | Runs |
| ------- | -------------- | ---- |
| v0.1.33 | 8, 1, 6, 1     | 4    |
| v0.1.32 | 40, 23         | 2    |

A traced source build went from 54 to 4, with main-thread hit testing down
from 1,058 ms to 33 ms. In the slow-glide pattern, one of four v0.1.33 runs
had 1.4 s of long tasks from idle table backfill; the other three dropped
3–6 frames.

## Limits

rAF pacing on the main thread is a proxy for visual smoothness, since the
compositor can scroll during main-thread work. Idle table layout can still
take 150–250 ms per table once scrolling pauses. No installation animation
was recorded, because that would capture the desktop.
