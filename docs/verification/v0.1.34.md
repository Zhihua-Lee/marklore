# v0.1.34 steadier link previews and formula backfill

## Changes

- **Link previews.** A hover preview no longer closes when the note
  re-renders around it. highlight.js finishing its lazy load re-renders notes
  that contain code; re-renders keep unchanged blocks, so the preview now
  closes only when its own link was replaced. On a slow machine a preview
  opened just before the highlighter arrived used to vanish; this was the
  v0.1.33 CI failure.
- **Formula and table backfill.** Idle backfills pause for 250 ms after
  scrolling. Their own reading-position corrections, made when content above
  the reading line grew, counted as scrolling, so deep in a long note a
  backfill could wait after every batch and take tens of seconds.
  `positions.js` now records where an instant correction left the scroller,
  and both backfills ignore it. Real scrolling still pauses them.

## Automated checks

All 59 unit tests and 154 browser cases (Edge; default and reduced-motion
projects, 2 workers) pass. GitHub Actions passed on the fix commit.

- A new case holds the highlight.js request until the preview is open, then
  checks that the preview stays after the re-render. It fails without the fix.
- The glide test previously failed 1 run in 6, on both this code and the
  v0.1.32 source (all formulas were not rendered within 15 s). It now passes
  10 of 10.
- The scroll-shield case records the raise with a MutationObserver and checks
  keys, wheel and pointer synchronously. Runners without animations end the
  scroll before a poll can observe the 150 ms raise.

## Manual/native checks

The packaged v0.1.34 build passes all nine native suites. On the first run,
`native.mjs` failed at the hover step: recorded trusted pointer events showed
the physical mouse at about (1230, 520) repeatedly pulling the pointer off the
link. It passed when rerun alone. Only synthetic notes and isolated profiles
were used.

## Limits

Physical mouse hardware was not exercised deliberately.
