# v0.1.36 tabs clickable again, optional smooth scrolling

v0.1.35 was built only locally for testing and not published; its changes
are included here.

## Changes

- **Tabs could not be selected or closed (v0.1.33 to v0.1.35).** Without a
  system title bar the whole toolbar was a window-drag region, with no-drag
  holes for its controls. Chromium ignores no-drag inside a scroll
  container, and the tab strip scrolls, so Windows answered `WM_NCHITTEST`
  with `HTCAPTION` over every tab and close button: clicks dragged the
  window. Now only an empty space after the new-tab button drags; a
  double-click there still maximises.
- **Optional smooth scrolling** (`Aa → 阅读导航 → 平滑滚动`, default off):
  `仅触控板` or `触控板、滚轮与滚动条`. Chromium and Edge move the page as input
  arrives, not in step with the display.
  - **Touchpad:** exponential smoothing, 34 ms.
  - **Wheel notches:** a critically damped spring, 70 ms, keeps speed
    continuous across notches.
  - **Scrollbar:** in the second mode the native scrollbar (dragged inside
    the browser, out of reach) is replaced by a page-drawn one with the same
    look. It is dragged on a spring (30 ms), and track clicks page.
  - **Native path kept for:** Ctrl (zoom), horizontal pans, line-based
    deltas and nested scrollers. The non-passive wheel listener exists only
    while the option is on.

## Automated checks

All 60 unit tests and 157 browser cases (Edge; default and reduced-motion
projects, 2 workers) pass. New cases cover:

- touchpad pacing and native fallbacks;
- merged wheel notches;
- the drawn scrollbar: placement, the thumb under the pointer, the page
  catching up, track paging;
- switching the option at runtime;
- migration of the unreleased `touchpadScroll` setting, including the
  boot-time merge over defaults. An earlier build silently lost it there.

## Manual/native checks

The packaged v0.1.36 build passes all nine native suites. The menu suite now
asks Windows directly: tab, close and toolbar buttons are `HTCLIENT`, and
the drag space is `HTCAPTION`. Before the fix, the packaged v0.1.36 build
returned `HTCAPTION` across the whole tab strip.

Local benchmarks in the real app used synthetic input:

- **Touchpad**, precise deltas every ~8 ms: the variation of the per-frame
  step (CV) fell from 0.30–0.38, with 6–11 stalled or doubled frames, to
  0.05–0.09 with none. The compositor presented all frames.
- **Wheel**, notches every 90 ms: the mean frame-to-frame speed change is
  1.4–1.6 px, against 1.8 for Chromium's own animation. Plain exponential
  smoothing reached 9.4 and was rejected.
- **Scrollbar**, drags at 125 Hz: the speed change fell from 70.4 px, with
  native steps like 121, 0, 122, 80, 40, to 1.7–3.8.

A whole-physical-pixel stride variant was also tried and rejected: its
deviation from the smooth path was higher at slow speed (RMS 1.1–1.9 px
against 0.5–1.1 px for plain rounding).

## Limits

Synthetic input does not pass through Chromium's input resampling. The
touchpad result was confirmed subjectively on the real device. A 60 Hz
display still blurs moving text (sample-and-hold). Smooth modes add one to
three frames of latency.
