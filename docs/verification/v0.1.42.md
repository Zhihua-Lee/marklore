# v0.1.42 live edit preview, editor find bar, reliable tab highlight

## Changes

- **Edit-mode preview followed typing only after a pause.** The refresh was a
  plain 160 ms debounce that every key reset. With a word every 120 ms, 25
  words left the preview 3.8 s behind on a 6k-character note and 5.4 s
  behind on a 146k-character note with 480 formulas. The refresh now waits
  for a short pause, but never longer than 80 ms, or three times the note's
  last render cost, from the first unrendered edit. The same measurement
  gives about 75 ms on the small note and 0.2 to 0.7 s on the large one.
- **Editor find bar.** CodeMirror's default form took the app's full-width
  input styles and had English labels. It is replaced by a floating bar
  like the reader's find, driving the stock `@codemirror/search` state and
  commands:
  - find as you type, starting from the cursor;
  - a match count, "无结果" and "正则有误";
  - toggles for case, whole word and regex;
  - previous and next;
  - replace behind an expand arrow.
- **Selected tab.**
  - The hover and focus shade of ungrouped tabs outranked the selected
    style. A clicked tab keeps focus, so it turned grey until focus moved.
  - The highlight waited for the note to render. It now moves on pointer
    press; a drag or a release elsewhere restores it.
- **Link preview closed after Copy.** Newer Chromium (CI's Edge, and likely
  Electron 44) blurs a focused button that disables itself, as Copy does
  while it writes. The card read that as leaving. This failed the v0.1.41
  CI run after that release was published. Focus dropping to nothing no
  longer closes the card while the pointer is on it.

## Automated checks

All 67 unit tests and 168 browser cases (Edge; default and reduced-motion
projects) pass. Each new case fails on the v0.1.41 code:

- the preview shows typed words while typing continues (0 of 8 before);
- editor find: focus, count, case, regex errors, replace all, Esc, and
  English labels;
- the selected tab under keyboard focus and hover, on press, and restored
  after a drag;
- the preview card surviving a focus drop with the pointer on it.

## Manual/native checks

The packaged v0.1.42 build passes all 11 native suites. The editor find bar
was inspected in screenshots in light and dark themes, with the replace row
open and closed.

## Limits

- Typing latency was measured with synthetic keys in Edge, not with an IME.
- On the large note, rendering while typing made the synthetic typing run
  about 27% longer. Input can wait up to one render (about 180 ms there).
- The Copy focus drop was reproduced by calling `blur()` in tests; it was
  not observed in the packaged app.
