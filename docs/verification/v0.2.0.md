# v0.2.0 Marklore: renamed, MIT-licensed, published from a clean history

## Changes

- **Name.** Folio Notes is now Marklore: a Markdown knowledge base whose
  notes stay plain files that people and AI tools can both maintain.
  "Folio" is taken by a GNOME Markdown notes app and a Mac Markdown library.
  - The window, tray and dialog text, the executable (`Marklore.exe`), the
    app ID and the file-association ProgID change.
  - Internal identifiers (`window.folio`, `FOLIO_*` variables, `folio:` IPC
    channels) stay.
- **Profile migration.** The profile folder is now named explicitly,
  `%APPDATA%\Marklore`. The first start renames `%APPDATA%\folio-notes` into
  it, keeping tabs, drafts, recent files and backups. If the old version
  still holds the folder, that start keeps the old one and the next start
  tries again. An isolated test profile never moves the real one.
- **Old registrations.**
  - Registering the file association, or changing start at login, removes
    the Folio Notes entries.
  - A Folio Notes login entry is reported as another version.
- **License and contributing.**
  - The project's own code and documentation are MIT-licensed; they were
    All Rights Reserved.
  - `CONTRIBUTING.md` sets out the scope and asks for an issue before larger
    changes.
- **History.**
  - The repository moves to `Zhihua-Lee/marklore`, pushed from a rewritten
    history: author and committer emails are the GitHub no-reply address
    throughout.
  - Every version tag points at a commit whose tree is identical to the
    original.
- **Tests stay in the background.**
  - Native suites run with `FOLIO_TEST_INACTIVE=1`, so the app shows windows
    without activating them.
  - The packaging wrapper hides the builder's console tools.

## Automated checks

All 71 unit tests and 168 browser cases (Edge; default and reduced-motion
projects) pass. The new unit cases cover:

- the profile migration: move, an existing Marklore folder wins, fresh
  install, failed move;
- removing the Folio Notes registry entries;
- reporting a Folio Notes login entry as another version.

## Manual/native checks

The packaged v0.2.0 build (`Marklore.exe`) was run through all 11 native
suites with windows shown inactive:

- 10 passed in the full run.
- `native-editing` timed out once on a hover step, while the user's mouse was
  in use; it passed on two reruns.

A foreground-window log, polled every 2 ms, recorded:

- no window from packaging;
- no test window from `native.mjs`, `native-language.mjs` and two
  `native-menu.mjs` runs, after its probe's `show()` became `showInactive()`;
- no window from the headless UI specs.

## Limits

- The profile migration was tested on temporary folders. It was not run
  against a real `%APPDATA%`, because Electron resolves that folder through
  Windows rather than an environment variable.
- The registry cleanup was checked through the command list, with `reg.exe`
  mocked.
- Test windows are still shown on screen, though inactive. A physical mouse
  over them can still disturb hover steps.
