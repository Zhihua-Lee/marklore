# v0.2.3 a Windows installer

## Changes

- **Installer.** `Marklore-Setup-v0.2.3-x64.exe` installs for the current
  user by default, without administrator rights, into a folder of the
  user's choice. A chosen folder whose path does not name Marklore gets a
  `Marklore` subfolder. It adds Start menu and desktop shortcuts and an
  entry in `Settings → Apps`. The installer and its pages are in Chinese or
  English, following the system language.
  - **Upgrading** replaces the program in place and keeps shortcuts, start
    at login and file registration.
  - **Uninstalling** removes the program folder and shortcuts. It removes
    the file registration and the startup entry only when they point at
    that installation, so a zip copy registered elsewhere keeps them.
    Settings and drafts in `%APPDATA%\Marklore` are kept; notes are never
    touched.
- **No portable mode in an installed copy.** Upgrading or uninstalling
  replaces the installed folder, so a `data` folder there would be lost.
  The setting explains this and points to the zip version, which is
  unchanged.
- **Docs.** The README install section offers both downloads and explains
  updating and uninstalling each; the user guide and development notes
  follow.

## Automated checks

- All 79 unit tests pass, including a new case: an installed copy is never
  portable and refuses to enable it.
- All 186 browser cases pass (Edge; default and reduced-motion projects).

## Manual/native checks

The packaged v0.2.3 build passes all 13 native suites, with windows shown
inactive.

- In the first run, `native-portable.mjs` timed out waiting for the restart
  after enabling portable mode. The browser suite was running at the same
  time, so the machine was heavily loaded.
- Run alone, it passed twice.

`tools/installer-check.ps1` passes all 32 checks on Windows 10 (per-user,
silent):

- installation, both shortcuts and the Apps entry, and no stray `debug.log`
  (one left in Electron's own folder had been copied into the build);
- a start with an isolated profile;
- uninstalling, which leaves another copy's file registration in place;
- an upgrade over itself, which keeps the registration and startup entry
  pointing at the installation;
- the final uninstall, which removes them.

The script backs up the existing HKCU registrations first and restores
them afterwards; the restored values were compared with the originals.

## Limits

- Only silent installs were automated. The installer's own pages were not
  driven, so that no window would take the foreground.
- Installing for all users (Program Files, with elevation) was not tested.
- The installer is not code-signed. SmartScreen warns on first run, as it
  does for the zip.
