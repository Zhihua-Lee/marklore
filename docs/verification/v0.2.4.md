# v0.2.4 full-text search, safe snippets, network drives

## Changes

- **Full-text search.** The search box above the library (`Ctrl+Shift+F`)
  finds notes by file name and text at once, as you type.
  - Each note is listed once with up to three hits: the section and the
    line around each, the words marked in names and lines, formulas
    typeset.
  - Every word must occur; quoted words match as a phrase. Names rank
    first, then headings, then the number of hits.
  - A hit opens the note at its line with the word marked by the find bar.
    The list stays; arrow keys move through it and `Enter` opens the first.
  - Results come from the library index in memory. With 5000 generated
    notes the worst query took about 0.25 s. In the packaged app, results
    were on screen about 0.1 s after typing.
- **Snippets keep their syntax whole.** Backlink cards, search results and
  anchor labels are cut outside formulas, LaTeX environments, code, links,
  inline HTML and emphasis. Previously a cut formula or an unclosed `**`
  rendered as noise.
- **Network drives.** Node's native `realpath` fails with `UNKNOWN` on
  WinFsp mounts (SSHFS-Win, rclone), so notes on such drives never opened.
  Paths are now resolved step by step when the native call cannot answer.
- **Large libraries.**
  - A home folder as the library was read so long that search, which
    waited for the whole scan, found nothing. The scan now goes breadth
    first, each note is searchable once read, and results say when more
    may come.
  - Python and conda environments, `node_modules`, `site-packages` and
    `__pycache__` are skipped. `.txt` files are no longer indexed.
  - A drive's root shows as `Z:\`.
- **Leaving folders out.** Right-click a folder in the library to leave it
  out of search and backlinks. Settings lists these folders, with a way
  back.
- **Index fix.** A note written twice in quick succession could keep its
  modification time, and the second write was skipped. Writes reported by
  the watcher are now always re-read.

## Automated checks

All 100 unit tests and 190 browser cases (Edge; default and reduced-motion
projects) pass. New cases cover:

- query parsing, matching, ranking and snippets;
- cuts that never break a span, tried at every position of a mixed line;
- the `realpath` fallback;
- breadth-first scanning, the skipped folders and search during a scan;
- excluded folders: dropped at once, ignored on change, restored;
- the search list, keyboard and name marks; the folder menu and the
  Settings list.

One browser case (history navigation) once clicked the copy of a link
inside an open link preview. It was rescoped to the note.

## Manual/native checks

The packaged v0.2.4 build passes all 13 native suites, with windows shown
inactive. `native-library.mjs` now also checks, in the real app:

- a note written twice quickly is found;
- a hit opens the note at its line, the word marked;
- an excluded folder's note never appears;
- results are on screen about 0.1 s after typing.

`tools/installer-check.ps1` passes all 32 checks.

On the reader's SSHFS-Win drive (read only, isolated profile, window
inactive):

- the v0.2.4-r2 build failed to open `Z:\AGENT.md`; this build renders it;
- a sequential scan of the drive's root read about 50 folders a second.
  It took about half a CPU core across Marklore and SSHFS. Most folders
  were experiment output, which the new exclusion leaves out.

## Limits

- Changes made on the server directly, not through the mounted drive, may
  not be reported by SSHFS; the refresh button or `Ctrl+R` reads them.
- Each start reads the library again; nothing is cached between runs.
- Matching is literal: no regular expressions, fuzzy matching or pinyin.
