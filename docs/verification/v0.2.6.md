# v0.2.6 reliable tab clicks and drops; diffs as an optional other format; contents in exports

## Changes

- **Clicking a tab switched to it only sometimes.**
  - Since v0.2.5, a pressed tab took the current tab's style at once, including
    its 100 px minimum width. A narrow tab after the current one grew under
    the pointer and its close button came under it, so the release landed on
    another element and the click was lost.
  - On press, now only the looks move: the pressed tab takes the current
    tab's card and the current tab gives it up, each keeping its width until
    the release. Releasing the pointer on the tab's own place activates it at
    once, also after the pointer wandered past the drag threshold and came
    back.
  - Reproduced in a browser case: on v0.2.5 code, a plain click on a narrow
    tab after the current one left the old tab current.
  - The first v0.2.6 build moved only the pressed tab's look on press, and
    the reader noticed a hitch on every switch. Measured with 16 large notes
    (formulas, code, tables; headless Edge): nothing changed for 0.5–0.6 s
    after the release while the note rendered. Moving the card on press puts
    the highlight on screen 24–72 ms after the press; the note follows the
    release in about 0.3 s, as before.
  - Deferring the switch to the frame after the release was tried and
    dropped: a shortcut or command right after the click then acted on the
    previous tab (four browser cases failed).
- **The outline is cached.** Every tab switch rebuilt the outline, and each
  heading label went through the Markdown parser and the sanitizer again:
  30–100 ms a switch for a note with 120 headings. Labels are now cached
  (keyed on whether KaTeX has loaded), and the step takes 2–5 ms.
  - Measured on the same 16 large notes: switching back to a recently viewed
    note took 200–370 ms in all, almost all of it the browser restyling and
    relaying the page (about 20,000 elements, 13,000 of them in 240
    formulas).
  - Rewriting the slowest CSS selectors was measured and not done: removing
    all 29 that Chrome cannot index saved about 7% of the style time.
  - Keeping recent notes rendered while hidden would avoid that cost. It was
    left for later, after measuring the reader's own notes, since it touches
    about ten modules that assume one content area.
- **Dropping a tab into a group.**
  - The drop was decided only while the pointer was over another tab. In a
    gap between tabs, or over the dragged tab's own old place (wide for the
    current tab), the tab was taken out of its group.
  - Now, between two tabs of a group (gaps included) or over one of them, the
    tab joins the group at that place. On the pill it goes to the end. In a
    gap at a group's edge, or over its own old place, it keeps the group it
    had. While dragging, the pill and the insertion mark show where it lands.
- **Other formats: diff / patch** (Settings → System; off by default).
  - While off, nothing changes: `.diff` and `.patch` files do not open, do not
    show in folders and are not registered.
  - On: they open from Open, by dropping, from folders and from links in
    notes. Each changed file becomes a section, titled by its path and
    added/removed line counts (new, deleted and renamed files are marked),
    listed in the outline and foldable. Added and removed lines take a soft
    wash on the code card, and a `format-patch` message stays on top.
  - Hunks are read by their line counts, so a removed `-- x` line is not
    taken for a `--- ` file header. When counts are wrong (hand-made patches),
    lines are read by their first character.
  - Read-only in the reader: no block editing or formatting tools. Source
    view shows the file itself, and reading positions map back to it.
  - Kept out of the library's index, full-text search and backlinks.
  - Registration: a separate `Marklore.Other` type ("Diff / Patch file") in
    the Open with list only, never the default. It follows the switch when
    this copy is registered, and the uninstaller removes it with the rest.
- `diff` code blocks in notes get the same line tints.
- **Contents in exports.**
  - A PDF now has bookmarks, nested by heading level (Chromium's
    `generateDocumentOutline`, which needs the tagged PDF it already made).
  - A formula in a heading was missing from its bookmark: its MathML is
    clipped and its drawing `aria-hidden`, so "1 傅里叶变换 F{f}(ω)" became
    "1 傅里叶变换 ". In a PDF export, a heading's formula drawing is now
    read instead. Superscripts are flattened (x² reads "x2"). Body formulas
    and HTML exports are unchanged. Chromium ignored an `aria-label` on the
    heading, so that route was not taken.
  - A standalone HTML page lists its headings beside the text (Settings →
    Export → Contents in HTML; on by default). The list is plain links, so
    the page still runs no script under its content policy. It sits above
    the text on a narrow screen and is left out of print. Headings keep their
    formulas in the list; links inside headings are unwrapped. A page with
    fewer than two headings gets no list.

## Automated checks

All 114 unit tests and 207 browser cases (Edge; default and reduced-motion
projects) pass. New cases cover:

- the drop rule as a pure function: between and over a group's tabs, gaps,
  the dragged tab's own place, folded groups;
- a narrow tab after the current one switching on one click, without
  resizing on press (fails on v0.2.5 code);
- a click whose pointer wandered and came back, and the current grouped tab
  dragged within its own place, both keeping order and group (fails on
  v0.2.5 code);
- a tab dropped between a group's first two tabs joining there (fails on
  v0.2.5 code);
- diff parsing (headers inside hunks, wrong counts, renames, deletions,
  format-patch messages, backticks) and position mapping;
- the diff reader: sections, outline, whole-line tints in both themes, no
  in-place editing, positions in the diff's own text, a `diff` block in a
  note;
- registration commands and the preference (other preferences kept), and
  file listing and opening gated by the switch;
- the heading list for HTML exports (levels, formulas kept, inner links and
  ids dropped, none for one heading), the switch on by default and saved, and
  the export document taking the list for HTML only and refusing anything
  else.

One earlier case changed with the design: a pressed tab now shows the
current tab's look through a `pressed` class, not the `active` class, and
the current tab gives it up (`leaving`); both keep their widths.

## Manual/native checks

The packaged v0.2.6 build (the third build, with the press look and the
outline cache) passes all 14 native suites, with windows shown inactive. The new one, `native-other-formats`, checks:

- a `.diff` given on the command line is ignored while the switch is off;
- with it on, the file opens read-only, one section per file;
- the file (CRLF line ends) is unchanged afterwards.

`tools/installer-check.ps1` passes all 36 checks. Four are new:

- the uninstaller removes this copy's `Marklore.Other` type;
- it removes that type's `.diff`/`.patch` Open with entries;
- no `.diff`/`.patch` class keys are left behind;
- the reader's Open with entries are as before.

Two faults in the script were found on the reader's machine and fixed:

- Its first run left two empty class keys (`.diff` and `.patch`, each with an
  empty `OpenWithProgids`) under HKCU. They had no effect and were removed;
  the script now removes class keys it created.
- **The script deleted the reader's own Open with entries.** It has done so
  since it was added in v0.2.3. These entries (`Marklore.Markdown` under `.md`
  and `.markdown`, and now `Marklore.Other` under `.diff` and `.patch`) are
  empty `REG_NONE` values. It read them through `Get-ItemProperty`, which
  reports them as missing, and restored them through `$(...)`, which turns
  an empty byte array into `$null`, so every one was removed. Its "removed"
  checks used the same reading and could not fail.
  - Found when the reader's `.diff`/`.patch` entries were missing after a
    run, with the rest of their registration intact.
  - The script now reads and restores these entries through .NET, and checks
    them afterwards (the fourth new check, which failed on the first fix,
    before the restore was corrected).
  - The reader's four entries were written back as Marklore's own Register
    writes them, and survived the final run.

Screenshots of a `format-patch` file were inspected in the light and dark
themes.

`native-export` now also checks, on the app:

- the PDF's bookmarks ("Export fixture", then "Folded section" below it);
- the HTML's list linking to both headings;
- with the switch off, an HTML export without a list.

A note with Chinese headings, a formula in two headings, a link in one and
four levels was exported both ways, read with `tools/pdf-outline.mjs` and
inspected in screenshots at 1280 and 600 px.

## Limits

- Only unified diffs are read as diffs. Other patch formats (context diffs,
  apply_patch blocks) show as plain text in a code block.
- Diffs are not highlighted by the language of the changed file.
- Turning the switch on registers the other type only when this copy is
  already registered; otherwise, use Register once.
