# v0.2.8 typing directly in the rendered note; Edit mode without the source pane; a first macOS build

## Changes

- **Typing directly in the preview** (Settings → Editing; experimental, off
  by default).
  - In Edit mode the rendered note takes typing. Each keystroke becomes an
    edit of the source at the exact offset its text came from (the text maps
    the preview already carried for locating and formatting). It is applied
    through the source editor, so undo and redo are that editor's history.
  - There is no document model and no conversion back to Markdown, so the
    rest of the file cannot change. No dependency was added.
  - Typing and deleting inside a run of text are left to the browser, and
    the source follows on the `input` event. Setting the caret from script
    cost about 15 ms a key in a long note (a forced layout).
  - The preview is not rendered again while typing goes on; it renders once
    typing stops, and the render cache is told which block was patched.
  - Enter starts a paragraph, a list item (an empty item ends the list) or a
    quote line; Shift+Enter breaks the line.
  - Backspace at a block's start first removes its marker (`#`, `-`, `>`),
    then joins the block to the one before; Delete at the end joins the next.
  - Backspace right after an inline formula, or Delete right before one,
    removes the whole formula.
  - Deleting a selection removes the text of each run and any whole inline
    element inside it. The markers of a partly selected bold, italic or link
    stay.
  - Input methods compose in place; the result goes to the source once, when
    the composition ends, and renders wait for it.
  - Formulas, code, tables, diagrams, images and HTML stay whole and keep the
    pencil. A plain click on a link places the caret; Ctrl+click follows it.
- **Edit mode without the source pane** (Settings → Editing → Show the
  source pane in Edit mode; on by default). Off, Edit mode shows the
  rendered note alone. The two settings combine freely.
- **macOS, step 1.** CI builds unsigned (ad-hoc signed) dmgs for Apple
  silicon and Intel as a workflow artifact. Changes for the Mac:
  - the traffic lights are inset into the toolbar, with an app menu and a
    Window menu;
  - files open from Finder (`open-file`);
  - closing the window hides it;
  - PingFang, Songti and Menlo fallbacks;
  - Cmd works in the shortcuts that took only Ctrl;
  - a `.icns` icon.

  Two faults found by the first CI run were fixed:
  - the README and licence files at the bundle's top level broke code
    signing; they now go to `Contents/Resources`;
  - excluded folders rejected POSIX paths (`/Users/...`).

  The Mac build has not been run on a real Mac and is not attached to the
  release.

## Automated checks

All 114 unit tests (also on macOS in CI) and 218 browser cases (Edge;
default and reduced-motion projects) pass. New cases:

- `direct-edit.spec.js` (8):
  - off by default;
  - typing changes exactly the typed text, also inside bold, and undo
    restores it;
  - Enter makes a paragraph and a list item; Backspace removes a heading's
    marker, then joins paragraphs;
  - deleting across bold keeps the markers;
  - an input method composes once, also at the edge of bold text;
  - Backspace and Delete next to a formula remove it whole;
  - Edit mode without the source pane is still editable.
- `window-controls.spec.js`: the macOS toolbar leaves room for the traffic
  lights, except in full screen.
- `excluded.test.mjs`: POSIX paths.

## Manual/native checks

The packaged v0.2.8 build passes all 14 native suites, with windows shown
inactive. `tools/installer-check.ps1` passes all 36 checks, and the reader's
Open with entries are unchanged afterwards.

Direct editing was measured in the browser (headless Edge):

- **Fidelity on 60 of the reader's own notes** (the 20 largest and 40 at
  random, 360 edits): a character typed in the middle of a random text run
  changed the source at exactly that offset every time, and each undo
  restored the file byte for byte.
- **Keystroke to the next frame, median.**
  - On a 13 k-character note with 132 formulas: 13 ms. Typing in the source
    pane takes 9 ms, but triggers a 60–70 ms render on almost every key.
  - On a 132 k-character note with 1,320 formulas and 27,000 elements:
    44 ms, with no render while typing. The source pane takes 20 ms, with
    0.6 s renders while typing.

## Limits

- Typing over a selection, Enter and joins render the whole note at once:
  about half a second on the largest note above.
- Input methods were tested through the browser's input-method interface
  (CDP), not with a real Windows input method at every kind of boundary.
- A space typed at the end of a run shows as a no-break space until the next
  render; the source gets a plain space.
- Tables are edited with the pencil, not cell by cell.
