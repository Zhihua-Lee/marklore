# v0.2.9 the caret stays put while typing directly in the preview

## Changes

- **Typing directly in the preview lost the caret after a pause.** The
  reader found that the caret kept jumping to the start of the paragraph.
  - When typing stops for a moment, the preview renders again and replaces
    the run of text holding the caret. The browser then left the caret
    between blocks. There it looked like the start of the paragraph, and the
    next keys were typed elsewhere or refused.
  - The check after a render only asked whether the caret was still in the
    note. It now keeps the caret only if it is on text, at the position the
    source editor holds; otherwise the caret is put back there.
  - Reproduced in a browser case on v0.2.8 code: after typing "AB" and a
    one-second pause, "CD" and "EF" were lost.

## Automated checks

All 114 unit tests and 219 browser cases (Edge; default and reduced-motion
projects) pass. New case: `direct-edit.spec.js`.

- Type, pause until the preview renders, and type again, from the keyboard
  and through an input method.
- All the text lands in order, in the source and on the page.
- The caret is on text afterwards.

## Manual/native checks

The packaged v0.2.9 build passes all 14 native suites, with windows shown
inactive. `tools/installer-check.ps1` passes all 36 checks, and the reader's
Open with entries are unchanged afterwards. The reader tried the build and
found the problem gone.
