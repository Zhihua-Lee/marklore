# v0.3.0 updates from inside the app

## Changes

- **Updates from Settings.** `Settings → Background & system → Version` shows
  the current version and checks GitHub for a newer release
  (`desktop/updater.mjs`).
  - One click downloads the new version and checks it against the release's
    `SHA256SUMS`. Marklore then saves tabs and drafts, quits, puts the new
    files in place and starts again.
  - The installed copy runs the new setup over itself. A zip copy, including a
    portable one, has its folder overwritten; nothing is deleted, so `data`
    stays. The program path stays the same either way, so the file
    association and the startup entry keep working.
  - The downloads use their own session: the default one still refuses every
    web request from notes.
  - "Check for updates at startup" is off by default. When on, it only
    reports a new version.
  - A zip copy in a folder that cannot be written to, and the Mac build, only
    point to the release page.
- **Why:** each new version used to be started from a new folder, and its
  file registration had to be made again.

## Automated checks

All 122 unit tests and 220 browser cases (Edge; default and reduced-motion
projects) pass.

- New unit tests: `tests/updater.test.mjs` (8 cases).
  - Version order and SHA256SUMS parsing.
  - Installed and zip updates hand the right files to the helper.
  - A download that does not match its checksum is refused and nothing runs.
  - After the restart the result is reported once.
- New browser case in `desktop-settings.spec.js`: check, download progress,
  then install, with one click.

## Manual/native checks

The packaged v0.3.0 build passes all 15 native suites, with windows shown
inactive. The new suite `native-update.mjs` updates a portable zip copy from
a local feed:

- the app downloads and checks the zip and quits;
- the helper replaces the files and starts the program again at the same
  path;
- the `data` folder is unchanged.

`tools/installer-check.ps1 -Newer` passes all 40 checks: the 36 before, plus
four for an in-app update of the installed v0.3.0 to a v0.3.1 test build.

- The update lands in the same folder.
- It keeps the file association and the startup entry.

The reader's Open with entries are unchanged afterwards.

A first try showed that Windows PowerShell started detached from Node never
runs. The helper is now started normally and waited for. It starts itself
again as a separate hidden process, then returns.
