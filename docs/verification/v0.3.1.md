# v0.3.1 faster direct editing, small updates, less memory

## Changes

- **Direct editing in long notes.** Each top-level block is its own editing
  host (`src/direct-hosts.js`), and structural edits render only their
  blocks. On an 1,800-line note with 480 formulas, measured keydown to the
  next frame (median of 40 keys):
  - typing: 38–41 → 18–22 ms;
  - Enter: 283 → 67 ms.
  - A closing `$`, backtick or `)` typesets at once. Table cells take typing on
    one line; a `|` is written `\|`.
  - Arrows, Shift selection, drag, Shift+click, Ctrl+A, Ctrl+Home/End and
    Page Up/Down cross blocks. Copy and cut of a selection over blocks write
    all of it.
- **The note stays put while editing.** The render after a pause moved the
  note up by 9–24 px: the reading anchor put a character's top where the probe
  point had been. Switching Read/Edit with the source pane landed one frame
  late, and tables were laid out again 80 ms or more later; both now happen
  in the switch's own frame.
- **Smaller updates.** Releases carry the app files alone
  (`Marklore-vX-app-electron-<electron>.zip`, 3.5 MB). A copy running the same
  Electron downloads that instead of the whole package. An installed copy's
  "Apps & features" version follows.
  - Fixed: the downloaded update was never removed (Electron's fs treats the
    unpacked `app.asar` as an archive), and a second update hung at 0%.
- **Smaller package.** Unused Chromium parts are left out (WebGPU shader
  compiler, Vulkan and SwiftShader) and the installer uses maximum
  compression: setup 105.9 → 92.9 MB, zip 149.2 → 129.5 MB. Any `debug.log`
  is dropped from the package.
- **Startup and memory.** The session is read while Chromium starts, and the
  page loads right after the window is created. Median first paint went from
  ~612 to ~571 ms (source build). After heavy rendering and 5 s of quiet, the
  renderer's garbage is collected: 334 → 249 MB on the long note with 20
  diagrams.

## Automated checks

All 125 unit tests and 229 browser cases (Edge; default and reduced-motion
projects) pass.

- New unit tests: the app-files update (both copies), another Electron taking
  the whole package, the helper setting the installed version.
- New browser cases in `direct-edit.spec.js`:
  - crossing blocks with arrows, Shift, a drag and Ctrl+A;
  - cutting over blocks (the clipboard has all of it);
  - block renders, table cells, a closing `$`;
  - the note keeping its place after the pause render. Without the fix this
    case moved 21 px.

## Manual/native checks

The packaged v0.3.1 build passes all 16 native suites, with windows shown
inactive.

- `native-gpu.mjs` (new) starts it with the GPU off: formulas, a table and a
  diagram still render. The removed files are absent.
- `native-update.mjs` updates a portable zip copy twice from a local feed,
  with the whole zip, then with the app files. Each time `data` is kept, the
  program restarts at the same path and the downloads are removed.

`tools/installer-check.ps1 -Newer` passes all 40 checks with a v0.3.2 test
setup. The installed v0.3.1 is updated twice in the app, with the setup and
then with the app files. "Apps & features" shows the new version. The file
association and the startup entry are kept.

The reader's Open with entries are unchanged afterwards.

## Limits

- Direct editing with input methods is tested through CDP composition events
  only.
- Updating from v0.3.0 takes the whole package: v0.3.0 does not know the
  app-files asset.
- The source pane's scrollbar still resizes while scrolling a long note
  (CodeMirror estimates lines it has not drawn).
