# v0.3.3 security update

Prompted by the 2026-10-21 security news (Node.js security release; eMudhra
intermediate CAs with guessable keys). Checkup and findings: the owner's
context store, topic `dev-security-checkup`.

## Changes

- **Electron 44.4.5 → 44.9.3.** Chromium 152.0.7977.130 → .167, plus
  backported ANGLE, Chromium, PDFium, Skia and V8 fixes. Its Node is 24.22.0;
  no Electron ships Node 24.22.1 yet.
- **Updates refuse eMudhra.** `distrusted()` in `desktop/updater.mjs`, applied
  with `setCertificateVerifyProc` on the `marklore-update` session: a chain
  through eMudhra fails (-2), anything else keeps Chromium's result (-3).
  Chrome blocks the eight intermediates by CRLSet, which Electron does not
  receive, and SHA256SUMS comes over the same connection.
- **Dependencies.** markdown-it 15.0.3 (GHSA-gfr2-rv44-r23c, quadratic-time
  rendering); Mermaid 12.2.0, which uses KaTeX ^0.18 (one KaTeX in the bundle
  instead of 0.16.47 as well) and chevrotain 13; overrides lodash-es ^4.18.1
  (GHSA-r5fr-rjxr-66jc) and source-map-js ^1.2.2; Vite 8.3.4.
- **CI.** `check-latest: true` (the runner's cached Node was 24.21.0; CI now
  reports 24.22.1) and `permissions: contents: read`.

Not affected: the Node.js CVEs (Brotli, TLS hostname, `dns.resolve`). The app
never uses Node's TLS, zlib or dns; updates go through Chromium
(`session.fetch`).

## Automated checks

- 126 unit tests pass (new: chains through eMudhra are refused, by
  organization and by name; a Sectigo chain is not).
- OSV, all 464 locked packages: 2 left, both build-time only and without a
  fixed version (http-cache-semantics, sprintf-js, from Electron's download
  tooling).
- Browser cases: CI (clean runner) 228 passed and 1 flaky (passed on retry).
  Locally 228 of 230 passed; the 2 failures were the long-note glide test
  (`reading-regressions.spec.js:144`) waiting for idle formula backfill on a
  machine at 80% CPU. The v0.3.2 code with its own dependencies fails it the
  same way under that load; on CI it passes in 9 s.
- The update session's check against GitHub's real chains (Sectigo for
  api.github.com and github.com, Let's Encrypt for release downloads):
  accepted, requests return 200 (`.local/cert-probe.cjs`).

## Manual/native checks

The packaged v0.3.3 build passes all 16 native suites, with windows shown
inactive, including two in-app updates of a portable copy (whole zip, then
app files).

`tools/installer-check.ps1 -Newer` passes all 40 checks with a v0.3.4 test
setup. The reader's Open with entries are unchanged afterwards.

## Limits

- No test certificate from the eMudhra intermediates exists here; the refusal
  is checked with constructed certificate objects shaped as Electron gives
  them.
- Copies on Electron 44.4.5 download the whole package once for this update.
