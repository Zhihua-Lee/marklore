# v0.3.4 direct editing: input methods kept, headings and code blocks

## Changes

- **Input methods no longer end halfway.** A headless probe showed the cause:
  the render about 600 ms after typing replaced the block being typed into
  and moved the focus to the new one, which Windows reports to the input
  method as a new text field (Sogou Pinyin then ends its composition).
  `src/render-cache.js` now keeps a typed-into block that renders the same
  text (`retyped`; only its source positions change) and updates the focused
  block in place otherwise (`keepFocused`, `morph`). Composing counts from
  the input method's first key (keyCode 229), not from `compositionstart`.
- **Headings.** Typing in a heading changed its id, so its section's key, and
  the whole section was rebuilt at each pause. An unmatched section now takes
  the leftover old section of the same level. Enter at a heading's end put
  the new paragraph outside any editing host, and the text typed next was
  lost; it now starts the section's body. Backlink counts in headings are
  kept by the in-place update and wait while an input method composes.
- **Fenced code blocks take typing** where their text is the source's (top
  level, not empty, not Mermaid): Enter keeps the line's indentation, Tab and
  Shift+Tab indent the selected lines, the closing fence's line break is not
  typed past, and selections reaching past the fences are refused.
- **Smaller fixes.** A deletion over several text nodes (Ctrl+Backspace
  across bold) did nothing; it deletes now. The render cache ignored
  `data-src-*` and `data-block-*` positions, so any edit re-created every
  later block with bold, links or escapes.
- **Tests.** Native-suite windows open off screen and out of the taskbar.

## Automated checks

- All 126 unit tests pass.
- Browser cases on CI: 232 passed (default and reduced-motion projects), none
  flaky. Locally, the 158 cases of the related specs passed (direct editing,
  editing, block editing, tables, backlinks, selection, copy, math, reading).
- New browser cases in `direct-edit.spec.js`: the block typed into keeps its
  element, its text node and the focus over the pause render (paragraph with
  bold and a formula, new paragraph); a heading keeps its section, text node
  and focus while typed into with an input method, and Enter after it types
  into the section; a code block takes Enter, Tab, Shift+Tab and typing after
  the pause, refuses edits past its fences, and code in a list keeps the
  pencil.
- A headless probe composed text (CDP `Input.imeSetComposition`) with pauses
  in headings of three levels (also with backlink counts), paragraphs, list,
  ordered, task and nested items, quotes, table cells, link text, inline code
  and a paragraph with a formula: no focus change and the same text node in
  each.

## Manual/native checks

The packaged v0.3.4 build passes all 16 native suites. A foreground logger
(GetForegroundWindow every 150 ms) recorded no Marklore window taking the
foreground during them.

`tools/installer-check.ps1 -Newer` with a v0.3.5 test setup: 0 failed. The
reader's Open with entries are unchanged afterwards.

## Limits

- Sogou Pinyin itself cannot be driven by the test tools; the fix is checked
  through the page's events and DOM. The owner tries it in the released app.
- In a code block, a typed character that changes how the line is
  highlighted makes the pause render replace that line's text nodes (the
  focus stays; the render waits while an input method composes).
