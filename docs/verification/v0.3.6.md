# v0.3.6 direct editing: no doubled paragraphs, empty notes and block prefixes

## Changes

A first pass by another agent (Gemini), reviewed here: each change was read
and probed, and five were corrected (below).

- **No doubled paragraph.** In v0.3.5, after Enter, a paragraph typed into
  showed twice after the pause render: the page-made empty paragraph kept its
  `direct-empty-block` class, so the render cache kept it beside the rendered
  one (reproduced on v0.3.5 with the new count assertions). Typing or an input
  method's text now clears the class, and the cache keeps such a paragraph only
  while it is still empty.
- **Empty blocks.** An empty note, heading, list item or quote gets an empty
  text run after its prefix (`markEmpty`), so the caret has a place; a click
  in the reader's blank area reaches the nearest block; a new note takes the
  focus in single-pane mode. Arrow keys and clicks over empty blocks no longer
  throw (`onLine` on a block without line boxes).
- **Block prefixes.** "# ", "- ", "1. ", "- [ ] ", "> " typed at a paragraph's
  start render at once on Space; "#" at a heading's text start raises its
  level.
- **Enter.** At a heading's or paragraph's start: an empty paragraph above,
  the caret in it. In a paragraph opened by an unclosed "$$": a line break, so
  display math can be typed line by line. At the start or end of open display
  math: a paragraph before or after it.
- **Formulas.** An unclosed "$$" is text: "$$x^2$" no longer shows "$" and an
  inline formula while the closing "$$" is being typed. A mouse press on a
  formula no longer moves the selection first, so a slow click is not lost.

Corrected in review:

- The paragraph start was taken as 1 when no blank line preceded it, so "$$"
  and Enter at a note's start did not work (`paragraphStart`).
- "#" at a heading with two spaces after its marks gave "# # Title"; it now
  goes after the last "#".
- Enter at a later line's start of a paragraph put the caret on a blank line
  that typing joined to the line above; it splits the paragraph there again.
- The "$$x^2$" fix refused any "$" after a "$", which broke "$a$$b$"; it now
  treats only an unclosed "$$" as text.
- A new test typed within 3 ms of the New button, before the focus arrived
  (1 failure in 8 runs); it waits for the focus now.
