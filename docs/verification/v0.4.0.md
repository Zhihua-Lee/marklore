# v0.4.0 AI assistants propose edits and comment through MCP

## Changes

- **MCP server.** Marklore is an MCP server: an assistant starts
  `Marklore.exe` in Node mode (`ELECTRON_RUN_AS_NODE=1`) with
  `<app.asar>/desktop/mcp.mjs`, the setup `Settings → AI assistant` copies
  for Claude Code, Codex or as JSON. It speaks JSON-RPC over stdio (no SDK)
  and finds the data folder as the app does. It reads only the libraries
  ticked in Settings (`ai/access.json`, re-read on every call), never hidden
  folders or folders left out of search, and resolves real paths before
  checking (a junction inside a library does not lead out of it). Tools:
  list_libraries, list_notes, search_notes, read_note, propose_edit,
  propose_note, list/get/withdraw_proposal, list/add/reply/resolve_comment.
- **Proposals.** The server never writes a note. An edit replaces exact old
  text that occurs once, checked when proposed and again when accepted. The
  note shows a bar: Preview renders it as it would read (changed text washed,
  changed blocks ruled, a deletion's place dashed) or as a source diff;
  Accept applies the edits as one undoable change and saves, or only adds
  them to the draft when the note has unsaved changes of the reader's own;
  Reject leaves it. A proposal that no longer fits can only be dismissed,
  and the assistant gets the reason. New notes preview in a tab and are
  written (`wx`) on accept. Unanswered proposals lapse after two weeks.
- **Comments both ways.** Select text, then the context menu, Ctrl+Alt+M or
  the toolbar's comment button; the passage is underlined and opens its
  thread in Read mode (reply, resolve, delete). Assistants list threads
  (`needs_reply` for the reader's), reply, resolve and start their own.
  Threads are found again by their text with 32 characters of context on
  each side. Both sides write a note's thread file under a lock.
- Proposals and comments live in the data folder's `ai` folder (moved with
  portable mode), not in the notes.

Found while verifying:

- The page needed each proposal's file path to match it to the open note;
  the main process left it out (the browser specs' mock had it). Caught by
  the new native suite.
- The Claude Code command put the server name right after `--env`, which
  takes several values; per Claude Code's documentation the name would be
  read as one more. Another option now sits between them.
- CI's temp folder has an 8.3 short name: a folder left out of search was
  stored under it, and the server compared it with the libraries' real
  paths, so it listed that folder's notes. Excluded folders are now
  resolved to real paths too (reproduced locally with a short temp path:
  2 failures before, none after).

## Automated checks

- All 143 unit tests pass (new: edits and the unified diff, including 300
  random round trips; the server over stdio; path limits; comment anchors,
  both-way threads and concurrent writers).
- Browser cases: 255 passed locally (all specs, one worker). On CI 251
  passed and 3 passed on retry: two older direct-editing cases and the known
  navigation-groups case, none touching this release's code.
- New browser cases: preview, source diff, accept and save; accepting into
  a draft and undoing it with one Ctrl+Z; reject; a stale proposal; a new
  note; Settings (libraries, copied setups); comments by click, context
  menu and Ctrl+Alt+M; no comments on an unsaved note.

## Manual/native checks

The packaged v0.4.0 build passes all 17 native suites, among them the new
`native-ai.mjs`: with the setup the app gives, the packaged program runs the
server from `app.asar`; it reads the opened library, proposes an edit and a
note, the app shows them and accepting writes them; an AI comment is
underlined, answered in the app and read back; unticking the library shuts
the server out. A foreground logger recorded no test window in the
foreground.

`tools/installer-check.ps1 -Newer` with a v0.4.1 test setup: 40 checks, 0
failed, including the in-app update.

## Limits

- The server was driven by the tests' own MCP client; connecting Claude
  Code, Codex or Claude Desktop themselves was not part of these checks.
- Comments are underlined in the rendered note only (not in the source
  editor), and a proposal's preview shows deletions in the source diff.
