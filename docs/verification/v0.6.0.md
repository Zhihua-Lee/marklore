# v0.6.0 Marks for the AI as context, background AI runs, one-button connect; tree file operations; page title

## Changes

- **Marks for the AI (src/marks.js, desktop/ai-bridge.mjs, mcp-tools.mjs).**
  The reader marks passages with what they want of the AI; marks stay on
  the notes until answered. Nothing is sent: an assistant connected over
  MCP reads them when told (`get_marks`), and the app writes what the
  reader is looking at (`context.json`: the open note when it is in a
  library open to AI, and the selected text) for `get_context`. Answers
  are proposals naming the marks they answer (`propose_edit` `marks`); an
  accepted proposal removes its marks, a rejected one leaves them open. A
  mark not acted on gets a reply (`reply_mark`); asked further, the
  exchange stays with the mark for the AI (`earlier`). Earlier open
  comment threads by the owner become marks once.
- **Background runs (desktop/ai-runs.mjs, claude-cli.mjs).** The app
  starts Claude Code once in print mode on the open marks: only
  Marklore's server (`--strict-mcp-config`, `MARKLORE_RUN` limits the
  server to the run's marks), no built-in tools (`--tools ""`), no user
  settings or hooks (`--restricted`), anything that would ask denied
  (`--permission-mode dontAsk`). Marks are claimed while it runs and
  released when it ends, fails, is stopped, times out (15 minutes) or is
  found left over at the next start. Claude Code is found on the PATH, in
  `~/.local/bin` or in the Claude desktop app's copy. A failed sign-in is
  reported in plain words.
- **One-button connect (desktop/ai-connect.mjs, src/ai-settings.js).**
  Settings writes Marklore's server into Claude Code's `.claude.json`
  (`CLAUDE_CONFIG_DIR` or home) and Codex's `config.toml` (`CODEX_HOME`
  or `~/.codex`), keeping everything else; shows connected, connected to
  another copy (or a copy no longer there), or not connected, and the
  number of live sessions. An unreadable settings file is left alone.
- **Proposal review (src/proposals.js).** Rendered/source and whole/changes
  switches; Accept all and Reject all write and end the review; change by
  change, the last decision ends it; no finish button. Reject (one or all)
  with a reason, read by the AI (`edit_reasons`, `owner_note`). Claude
  Code listening on a channel is told when its proposal is decided
  (desktop/mcp-channel.mjs).
- **Library tree (src/library.js, desktop/files.mjs).** New note or folder
  named in place, rename (F2; open tabs follow; links to the old name are
  counted), show in folder, Recycle Bin (Delete); library folders move up
  or down or leave; an outside folder can join.
- **Page title (src/properties.js, src/rich/properties.js).** A `title`
  property is shown above the properties line (not as a fold-able
  heading), once when the body starts with the same level-one heading,
  and edited in place in Edit mode.
- Outline labels of anchored blocks with formulas no longer repeat TeX;
  outline jumps in Edit mode land below the format toolbar.

Found while verifying:

- A background run started from an agent's own shell inherited that
  session's `CLAUDE_*`/`ANTHROPIC_*` variables and failed to sign in with
  no tokens used; a Marklore started normally does not have them. With
  them removed, a run on a temporary library took 12 s: one proposal, one
  reply on the mark that asked for a question.
- When the command-line Claude Code's own sign-in had run out, the run's
  error was Claude Code's raw message; it now says to sign in once in a
  terminal.
- The unit test for runs read the run's folder before it was removed; the
  folder now goes before the run reads as ended.

## Manual/native checks

The packaged v0.6.0 build passes all 17 native suites. The AI suite
connects Claude Code with one button into a temporary settings folder,
starts the server from the written entry, reviews proposals, reads the
open note and its mark with `get_context`, answers it with a proposal, and
hands a mark to a background run.

`tools/installer-check.ps1 -Newer` with a v0.6.1 test setup: 0 failed,
including the in-app update of the installed copy.
