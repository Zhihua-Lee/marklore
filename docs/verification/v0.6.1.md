# v0.6.1 Smooth long notes, the Edit-mode palette, fixes from a review of the code

## Changes

- **Style cost of long notes (src/style.css, proposals.css, layout.css,
  sections.js, appearance.js).** Selectors with `:has()` anchored on what
  holds the note (`.note-section:has(...)` for the hovered section,
  `body:has(#sidebar[hidden])` for the proposal bar and the panel tops)
  made every node put into the note restyle all of it. While formulas
  were still being drawn in idle slices, each slice paid that cost, so
  reviewing a proposal or highlighting in Edit mode stalled. The hovered
  and focused section are now classes kept by `watchSections`, and the
  panels' state is `data-*-dock` / `data-*-buttons` on `.workspace`.
  `tests/styles.test.mjs` fails on any such selector.
  Measured headless on a generated note of 110,000 characters with about
  1,300 formulas: putting one node into the note 85 ms → 1.5 ms; long
  tasks while all formulas are drawn about 20 s → 5 s; "next change" and
  "accept one" in a review 0.8–1.2 s → 0.3–0.4 s; long tasks after the
  first highlight in Edit mode about 5 s → 0.1 s.
- **Edit-mode palette (src/rich/bubble.js).** The palette opened by a
  right click on the highlight or colour button of the small toolbar
  closed at once.
- **What Edit mode writes (src/rich/markdown.js, math.js, editor.js).** A
  block written with escapes is checked to read back as shown; addresses
  with spaces keep their angle brackets; new neighbours get a blank line;
  a fence is lengthened past any fence line in its code; a pipe in a
  cell's code stays escaped; footnote references are not escaped; an
  empty task item stays a task; typing beside a wide list marker, an
  entity or a link by reference changes only what was typed; places in
  blocks with long differences (tables) are mapped.
- **Read-mode formatting (src/markdown.js, selection-tools.js).** Inline
  spans and text are found from where the block's content starts, past
  code spans over several lines, inline footnotes and formulas; a row
  with two dollar amounts is not taken for math; a closing tag is matched
  by its whole name.
- **Shell (src/app.js, backlinks.js, document-sync.js, marks.js,
  rich/editor.js).** A note that finishes loading after another became
  active is not shown under that one's tab; folds, anchors and the
  outline in Edit mode read the note in the editor; the conflict state is
  cleared on reload; a mark whose passage is gone still opens its card.
- **Main process (desktop/library-watch.mjs, link-index.mjs, files.mjs,
  main.mjs, folder-index.mjs, updater.mjs, integration.mjs).** Folder
  renames, moves and removals reach the index; a folder with an open note
  deep inside can be renamed; a write error while downloading an update
  is reported and settles; byte-order marks, `%26` in links and `#` in
  file names are handled; a second instance resolves relative arguments
  against its own folder; `reg.exe` output is read in the console's code
  page.
- **AI backend (desktop/ai-runs.mjs, ai-bridge.mjs, ai-store.mjs,
  mcp-tools.mjs, mcp-channel.mjs, ai-connect.mjs, proposal-edits.mjs).**
  Run ids are checked before anything is removed; the innermost library
  containing a path wins; the heartbeat keeps a session counted;
  `list_notes` filters by folder before its limit and `search_notes` says
  when it stopped; listeners are attached before waiting; access is
  cached after a successful write; proposals are settled under the lock;
  the Codex table is replaced without its neighbours' comments, with the
  file's line ends, also when written on one line; differences are
  trimmed by character, not code unit.

Left from the review: in `[x](foo)foo` a place in the second "foo" can
map into the link's address (the mark or selection is then off for that
block); `src/find.js` and `src/commands.js` suspicions that could not be
reproduced.

## Limits

- The timings are from a generated note in a headless browser, not from
  the packaged app on a real note.
- Still slow on that note (about 0.5–1 s): leaving the source or compare
  view of a review, the first "changes only" view, opening a review and
  returning from Edit to Read mode. Each lays out or renders the whole
  note once.
