# v0.6.2 The folder tree stays still on saves; formulas stay drawn while formatting

## Changes

- **Folder tree (src/library.js).** A save replaces the note's file, which
  the watcher reports as a change of the library, so the tree was rebuilt
  on every save and its open folders were filled a moment after it was
  shown. Open folders are now filled before the new tree takes the old
  one's place, and a refresh whose tree shows the same names, order and
  open folders (`shown()`) changes nothing: the focus and a name being
  typed stay. The scroll place is set once; the second reset after 150 ms
  is gone.
- **Formulas in Edit mode (src/rich/math.js, editor.js).** A change to a
  paragraph makes the editor draw its formulas again; they showed their
  TeX until the next frame, when they were seen to be near the screen.
  Formulas now wait to be near the screen only while a whole note is put
  into the editor (`wholeNote()`); one drawn again by an edit is typeset
  at once, except while an input method is composing.

## Automated checks

- All 190 unit tests pass.
- Browser cases locally: 303 of 303 passed (both projects, one worker). CI for
  640e15c (current Edge, and the macOS build): passed.
- New browser cases: a refresh with nothing new causes no mutation in the
  tree; a real change never shows an open folder empty
  (`library-refresh.spec.js`); bold and undo beside a formula never show
  its TeX (`rich-toolbar.spec.js`).

## Manual/native checks

  the edit; it was also watched frame by frame in a headless browser, not

- In the plain (not rich) editing path, Bold moved the scroll place by a
  few pixels in a probe; not looked into.
