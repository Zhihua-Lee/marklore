# v0.6.3 Properties, image layout, formulas in selections, and long notes that stay smooth

## Changes

- **Formatting inside other emphasis (src/rich).** Highlight, colour,
  bold, italic or strike applied to a selection that lies inside or
  across other emphasis marks only the selected text. Each candidate
  edit is checked by rendering it; HTML tags are the fallback where
  Markdown delimiters would not parse.
- **Incremental rendering (src/render-cache.js and others).** An edit to
  a long note renders again only the blocks it touched; inside a long
  list or table, only its items or rows. A selection across a formula
  shows it selected as one box, and its glyphs are never shown selected
  one by one.
- **Properties (src/rich/properties.js, src/app.js, src/editing.js).**
  A note without properties gets them from a button at the end of the
  format toolbar of Edit mode and from the menu. Optional: default
  properties for new notes, and a `modified` time kept on save (both
  off by default). Keys typed right after Ctrl+N go into the new note.
  The unsaved mark returns with the first edit after a save.
- **Images.** In Edit mode an image resizes by its handles, aligns from
  its box, and goes beside other images or text by dragging; columns
  hold text beside images. A changed image is stored as `<img>` with a
  percentage width; untouched images stay Markdown. Images nobody sized
  keep to a default size range and their pixel density.
- **Long notes.** Edit mode skips long lists off screen without moving
  them (`src/rich/rich.css`, `src/rich/editor.js`). Switching from Edit
  to Read finds the reading place without laying out the whole note
  (`src/positions.js`). A scroll made by code right after a jump lands
  is not undone.
- **Reading place and list heights.** Switching between Read and Edit
  keeps the line read inside a tall paragraph: both modes record the
  character at the reading line and its height in the pane
  (`src/rich/editor.js`). A list is as tall in Edit mode as when read:
  loose lists, and lists that start or end with a code block, formula,
  quote, table or heading (`src/rich/rich.css`, `src/style.css`,
  `src/rich/markdown.js`).
- **Selections with formulas, Read mode (src/positions.js,
  src/selection-tools.js, src/marks.js, src/app.js).** A mark for the AI
  is made also where the selection ends in or beside a formula, or
  between blocks; a partly selected formula is taken whole, a code block
  too, with both fences. The format bar formats a selection that ends in
  a display formula, a code block or the next block. A formula
  double-clicked with the format bar on is selected, as a word is.
  Spaces at a selection's edges stay outside the markers.
- **Emphasis next to CJK punctuation, Read mode (src/selection-tools.js).**
  Every bold, italic or strike that adds the format is checked as
  rendered: it joins an adjacent run of the same format, else uses plain
  delimiters, else HTML tags for that piece only.
- **Selections with formulas, Edit mode (src/rich/math.js,
  src/rich/editor.js, src/rich/commands.js, src/rich/inline-writer.js,
  src/rich/markdown.js).** A drag that ends or starts in an inline or
  display formula takes it whole; an inline formula can be selected on
  its own (double click, or a drag starting on it); a click opens a
  formula when the button is released. Overlapping marks are written
  nested so their Markdown closes; bold over text and part of a bold run
  extends the bold; emphasis whose markers would not work next to CJK
  punctuation is written as HTML tags. Highlight, colour and marks leave
  spaces at the selection's ends out. A footnote reference or inline
  HTML opened by a click stays open.
- **Opening long notes (src/offscreen-blocks.js, src/proposals.js).**
  Parts whose formulas are drawn are skipped off screen while the rest
  are still being drawn; formatting no longer searches the whole note
  for review marks when no proposal is shown.
- **Automated runs.** Windows of the app and of the UI tests' browser
  open off screen, no tray icon is made, and the tray is removed on any
  exit (`desktop/automated.mjs`, `tests/launch-app.mjs`,
  `playwright.config.mjs`).

## Measurements

On a generated note of about 2,900 lines with 1,300 formulas, old and
new builds run alternately, medians:

- Edit mode, wheel scroll from top to bottom: frames over 50 ms 221 to
  1; 95th percentile frame 61 ms to 21 ms.
- Edit to Read: longest frame 935 ms to 480 ms.
- Read to Edit: unchanged, about 450 ms.

On a generated note of about 4,000 lines with 4,400 formulas under one
top-level heading: time from opening until the page is quiet 28-36 s to
16-21 s; frames over 100 ms 64-118 to 9-16. Formatting in Read mode on
the settled page, in the app: 145-186 ms to 104-147 ms (Edit mode
48-92 ms).

## Limits

- What remains of a mode switch is the layout of the pane that was
  hidden; its cost grows with the note. On a generated note of 220
  sections, Edit to Read took about 2 s before and after these changes.
- Small height differences between the modes remain: a list ending at
  a fourth nesting level is 5.6 px taller in Edit mode, tables are
  about 1.8 px shorter there, and the first block of a note sits about
  1.5 px lower. Reading places are kept by character, so they do not
  move the place on a switch.
- After Read to Edit the text is no longer moved down below the
  floating toolbar, so the top line can sit under it.
- Formatting in Read mode remains slower than in Edit mode: each format
  edits the source, renders the changed blocks, shifts the positions of
  the later blocks and finds the selection again.
- Remaining selection differences: in Read mode, double click then
  Shift+click onto a display formula above drops the word; a footnote
  reference at a drag's end is left out in Read mode; inline HTML such
  as `<kbd>` partly selected in Edit mode is split.
- The scroll and switch timings were taken in a headless browser, not
  in the packaged app.
