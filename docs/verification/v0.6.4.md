# v0.6.4 One name per note, a library organised from the tree and contents pages, folding one level at a time

## Changes

- **One name per note (desktop/note-names.mjs, src/library.js and
  others).** A note's name is its leading level-one heading; the tree, the
  index view and the rename box show it. A rename, or a save that changed
  that heading, renames the file, the index entry, the heading, a `title`
  property and the links to it (heading anchors too) in one step with one
  undo. "Unify names…" lists every change for a folder before making it.
  No two headings of a note share an anchor (`a`, `a-1`, `a-2`, in the
  JavaScript and the Rust index alike).
- **Library hierarchy (desktop/note-moves.mjs, src/library.js,
  src/tree-dialogs.js and others).** Notes
  and folders move by menu or drag (the list scrolls near its edges),
  child pages move with their note, and notes are indented into child
  pages from the tree. Links in other notes are listed and rewritten only
  when the reader agrees; open tabs and drafts, AI marks and proposals and
  recent notes follow; every rewritten file is backed up and the last
  rename or move is undone in one step. Links and index entries broken by
  renames made in other programs are repaired from their menu.
- **Index view (src/folder-index-view.js, .css).** `_目录.md` and
  `SUMMARY.md` read as a book's contents with first sentences and missing
  entries marked; subfolders expand in place; a library without a
  contents file gets a generated, read-only one. Its own entries are
  edited in Edit mode with undo. Type size and weight follow an entry's
  role, folded level-one rows share one pitch, and every level-one entry
  but the first has the same half-line space above it.
- **Path line (src/breadcrumb.js).** Library, folders and parent pages
  above notes and index views; each `›` lists the siblings.
- **Folding and outline (src/app.js, src/outline.js).** "Expand one
  level" and "Collapse one level" (`Alt+Shift+]` / `Alt+Shift+[`;
  Shift+click collapses to level one) for note sections and index views.
  A note's leading heading is its title, not a section. The outline lists
  level-one entries on an index view and stops following once the reader
  scrolls it, resuming on an entry click, a note switch or a scroll after
  the marked entry is back in view.
- **Read and Edit layout (src/style.css, src/rich/rich.css,
  src/table-layout.js).** Lists nested to any depth, tables (the column
  widths optimiser now runs in Edit mode too) and a note's first block
  have the same height in both modes.
- **Typing in the source editor (src/editor-heights.js).** Measuring line
  heights in idle time waits until typing, selecting and pointer use have
  stopped; the scroll it restored could flush a keystroke against a stale
  selection and move the caret back one character.
- **Formulas in long notes (src/formula-hydration.js).** Drawn in idle slices
  as long as the frames between them, and a click, drag or key waits no
  longer than one slice.
- **Rules as test vectors (tests/vectors/, desktop/settings-schema.mjs).**
  Names, links, indexes, proposals, marks and settings are stated as
  language-neutral vectors that the JavaScript modules are tested against.

## Automated checks

- All 397 unit tests pass.
- Browser cases locally (Chromium headless shell): 495 of 500 passed on
  the full run. Two failed to load the page while the machine was loaded
  and passed when run again; the Read/Edit parity case for wrapping
  tables measured before the column optimiser had settled (the same on
  the previous commit, 0 of 8 under load on both); and
  `mode-switch-position` found a real change: the anchor between blocks
  moved to an inner element. That was fixed (61e9f06) and the position,
  index-view and outline specs pass (80 of 80).
- CI for a5e0c0e (Windows, current Edge): 499 browser cases passed and 1
  was skipped (the platform-font case, which needs the fonts of a
  desktop); the unit tests passed (2 native-index cases skipped without a
  binary). On the two pushes before it, two cases ran over
  the 30 s test timeout: the parity case above (34 s) and the
  scroll-over-formulas case, which slows the CPU four times (23 s on CI
  at v0.6.3). Timed against v0.6.3 at an eight-times slowdown, the app is
  as fast as before (17–19 s for both); both cases were given a longer
  timeout.
- New browser cases include: one-level fold buttons
  (`fold-toggle.spec.js`); index typography and the steady level-one gap,
  where folding a group moves the rows below by exactly its children's
  height (`index-view-look.spec.js`); the outline pausing and resuming
  (`outline.spec.js`); connected navigation (`nav-connected.spec.js`);
  Read/Edit parity for deep lists, tables and first blocks
  (`list-layout.spec.js`).

## Measurements

- Typing "GROUP DRAFT" after Control+End in the source editor
  (`navigation-groups.spec.js`, 60 repeats in each motion project): 6 of
  120 runs left the caret one character back before the change, 0 of 120
  after.
- Read/Edit height differences: lists ending at the fourth level or
  deeper +5.6 to +6.4 px → 0; tables −2 px → 0; wrapping tables up to
  +126 px → 0; first block in a narrow window +10 px → 0.
- Keeping the hidden pane laid out was measured as a way to speed up
  switching modes (3 launches per variant, 2 long notes): medians 0–27%
  faster, more frames over 100 ms and 120–400 MB more memory. It was not
  adopted.

## Limits

- In Read mode, a sortable table whose first column is narrower than its
  header and sort mark wraps the mark onto a second line; Edit mode does
  not. A leading `<details>` block is a card in Read mode and a compact
  fold in Edit mode.
- Expanding one level stays folded when the next level has more than 300
  rows; page counts of deeper subfolders appear once they are expanded.
- Undo covers only the last rename or move; nested index sections refresh
  only when expanded again after an outside edit.
