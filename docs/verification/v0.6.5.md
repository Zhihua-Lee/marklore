# v0.6.5 Reading styles, a bundled Chinese face, Settings in pages, Read and Edit drawn alike

## Changes

- **Reading style (src/appearance.js, src/style.css, src/export.js).** A
  new setting 排版风格 / Reading style: Standard (the line height, block
  spacing and heading sizes of v0.6.4, the default), Relaxed (line height
  1.85, spacing about 15% wider) and Compact (a tighter four-step rhythm
  that fits more on a screen). HTML export follows the style chosen.
- **Column width.** A separate setting: fixed (about 680 px, the
  default), with the window (up to 56em) or by characters (42em).
  "Restore default typography" resets typeface, size, weight, style and
  column width.
- **A bundled Chinese face (package.json, src/typography.js).** Noto Sans
  SC as a variable font (`@fontsource-variable/noto-sans-sc` 5.3.1, OFL)
  comes first in the note and interface stacks, so every weight step is
  drawn as set for Chinese too. Weights: auto, 300, 350, 400, 450, 500,
  550 (a stored 600 reads as 550); auto is 450 on screens at up to 125%
  scaling in the light theme and 400 otherwise; bold is at least the body
  weight + 150. HTML export embeds only the font subsets a note uses.
- **Size across screens.** The note's type grows slightly on wide windows
  (×1.0 at 1366 CSS px or less to ×1.09 at 1920 or more), on top of zoom.
- **Formulas and punctuation.** Punctuation right after an inline formula
  never starts a line, and long formulas still wrap at their operators.
- **Anchors.** A line holding only `<a id="…"></a>` takes no space in
  Read or Edit mode, and an anchor before a note's title no longer stops
  the title from being found (it shifted the whole outline one level).
- **Read and Edit drawn alike (src/rich/sections.js, src/style.css and
  others).** Sections, lists, tables, sortable tables, details cards and
  code blocks have the same spacing and heights in both modes; the Edit
  mode's section nesting is kept by a plugin that updates only on
  structural changes, so typing stays as fast as before.
- **Settings in pages (src/appearance.js).** One section per page with a
  line saying what it covers, the last page remembered, a search over
  every setting that lists matches by section, and keys (↑/↓,
  Ctrl+PageUp/PageDown, Esc). The tray's settings item opens its page.
- **Previews.** Link and tab previews give more of their box to the note
  (less chrome around it).
- **Library search (src/library.js, src/library-search.css).** A result
  is named as the tree names the note, the title's own line is not listed
  again, a section is named once for the hits under it, a line shows at
  most three rows, and the side lists scroll with a thin bar.
- **Backlinks card (src/backlinks.js, .css).** One interface face, aligned
  labels, snippets of at most three lines without list markers or task
  boxes, a quieter count badge.
- **Folding long notes and contents pages (src/folder-index-view.js,
  src/outline.js).** First sentences arriving in a contents view are put
  into its rows instead of drawing the view again, "Expand one level"
  opens entries already drawn in place, and the outline finds its
  headings in one pass.

## Measurements

- Contents page with 792 pages (four levels): "Expand one level" from
  247 ms to 43 ms (click to the second frame after it); the long task
  after it went from 211 ms to none.
- Note with 520 sections: each fold also looked up every outline entry's
  heading with its own query (about 55 ms on this note); now one pass.
  Folding the whole note still takes about 100 ms, the browser's layout
  of the content shown or hidden.
- HTML export of a Chinese note embeds the font subsets it uses: 0.4 to
  1.7 MB (base64) for the notes measured (80 to 870 distinct characters).
- Edit typing on a long note (median keystroke to frame): 19–20 ms with
  the section plugin, 20–21 ms before it.

## Limits

- Folding the whole of a very long note (hundreds of sections, thousands
  of formula elements) still takes about a tenth of a second.
- The first time a subfolder of a contents page is expanded, the page is
  drawn again once its entries have been read.
- HTML exports of Chinese notes are larger by the embedded font subsets.
