# v0.6.6 A serif default matched across scripts, text antialiasing, a phone reader

## Changes

- **Default typeface (src/reading-fonts.js, src/appearance.js,
  src/typography.js, vite.config.mjs).** The default reading typeface is
  now Source Serif 4 for Latin with Noto Serif SC for Chinese (both OFL,
  bundled as variable fonts; `@fontsource-variable/source-serif-4` and
  `noto-serif-sc` 5.3.1), the Latin design Noto Serif SC was drawn to
  match. Each script is tuned separately:
  - Latin faces use `size-adjust: 113%`, so Source Serif has the x-height
    the default face had; Chinese stays 16 px, so size, rhythm and formula
    scale are unchanged.
  - Song strokes are lighter than Latin ones at the same nominal weight, so
    Chinese gets one `@font-face` per weight in use, pinned with the
    `font-variation-settings` descriptor to that weight + 100. The weight
    row says so.
  - "Auto" weight is 100 heavier for this pairing (500 on high-DPI screens
    or in the dark theme, 550 otherwise).
  - The setting key is `serif`; a stored `literata` moves to it. Literata
    is no longer bundled.
  - HTML export embeds the same faces, only the subsets a note uses, and
    Chinese inside formulas follows the body face.
  - Font URLs come from one virtual module, so the dev server no longer
    loads a module per font file.
- **Text antialiasing (desktop/text-rendering.mjs, desktop/main.mjs).** A
  setting 文字抗锯齿 / Text antialiasing: Auto (grayscale at 200% display
  scaling and above, ClearType below; the default), Grayscale, or Color
  (ClearType). It applies after a restart.
- **Microsoft YaHei (system)** joins the typeface choices.
- **Fonts arriving (src/offscreen-blocks.js).** The parts of a long note
  skipped while off screen were re-measured whenever any font finished
  loading, so the first format in a session (the toolbar's Chinese labels
  load a subset of the interface face) restyled the whole note. Now only a
  face the note is set in that covers a character it has re-measures it
  (`fontsMatter`, `tests/offscreen-fonts.test.mjs`).
- **Dark theme.** Body text in the dark theme is slightly dimmer
  (`#d3d0ca`, was `#e4e2de`), and interface text with it.
- **Phone reader (mobile/, new).** A read-only web app for reading a
  OneDrive folder of notes on a phone, installed from Safari with "Add to
  Home Screen" and published with GitHub Pages
  (`.github/workflows/mobile-pages.yml`):
  - Microsoft sign-in with PKCE (no secret; files read-only), incremental
    sync with Graph delta, notes kept on the phone (IndexedDB) and readable
    offline and after the sign-in expires.
  - Note text is synced in full (search, links); images download when a
    note shows them, or all of them with "download all images for
    offline".
  - Home is the folder's `_目录.md` as the desktop's index view, read-only,
    with the desktop's parser, first sentences, styles and default
    folding; notes render with the desktop renderer.
  - Requests that stall time out and retry; each build is a new service
    worker and an open page reloads into it.

## Automated checks

- Unit tests: 416 pass; the interface text check passes.
- Browser cases locally (Chromium headless shell) on 96dee68: all 529
  pass. New cases cover the antialiasing setting, the YaHei choice, the
  serif pairing and its weights, and export of the pinned faces.
- CI on 4e3495c, 79d175f and 0dc9572 failed one case,
  `format-flash.spec.js:231`: after a bold above a long table, 115 blocks
  were skipped against 122 before. An instrumented local run showed the
  cause: the format toolbar's first appearance loads a subset of the
  interface face, and every font arriving re-measured the whole note. Fixed
  in 96dee68 (see Changes); the skipped count now holds right after that
  font arrives (121 and 115 in the three format cases), where it fell to 0.
- Phone reader (`tests/mobile`, iPhone viewport, Chromium and WebKit): 19
  pass in each, against a mock back end and a simulated Microsoft sign-in
  and OneDrive; offline start and reload into a new build pass against a
  preview build (Chromium; Windows WebKit cannot emulate offline with a
  service worker).
- CI for 96dee68 (Windows, current Edge): 528 browser cases passed and
  one passed on its retry (`parity-sweep.spec.js:475`, a block 128 px
  taller in Edit than in Read on the first attempt); the three format
  cases passed first time, in 13–16 s against about 27 s before the fix.
  The unit tests passed; the macOS job passed.

## Measurements

- Weight evenness of the default pairing, measured from rendered pixels
  at device pixel ratios 1 to 3.5, light and dark: Chinese/Latin stem
  width 0.81–0.87 and colour (ink per line) 1.16–1.26, near the 0.8 and
  1.3 of Noto Serif SC with its own Latin. Literata beside Noto Serif SC
  measured 0.67 and 1.03.
- Phone reader with an 800-page library and the CPU slowed 4×
  (Chromium): home with its contents 1.2 s, search 0.9 s, opening a page
  0.6 s.

## Limits

- The text antialiasing setting applies after a restart.
- The phone reader is checked on a phone by the owner, not in CI: sign-in
  returning into the home-screen app, keeping the screen awake, and iOS
  storage limits.
- Folding the whole of a very long note (hundreds of sections) still takes
  about a tenth of a second.
