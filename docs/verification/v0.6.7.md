# v0.6.7 Diagrams drawn as figures

## Changes

- **Diagram size (src/diagrams.js, src/diagrams.css).** Ondine drew every
  Mermaid diagram with 16 px text and at its full height, and the page only
  capped its width, so a top-down flowchart could be several screens tall
  (the example below was 457 × 1138 px). Now:
  - Ondine gets `fontSize` = 0.8 × the note's text size (rounded; 13 px
    at 16 px), `responsive: false` and `maxWidth` = the column width.
  - A diagram is never drawn larger than Ondine made it. Its height is
    capped at min(480 px, 60 % of the window): if a scale of 0.8 or more
    fits, it is shrunk to fit; otherwise it is drawn at 0.8 (text stays at
    about 10 px or more), cut off at the cap with a 32 px fade
    (`fitScale`).
  - Sizes are recomputed when the column or the window changes
    (`ResizeObserver` and the window's `resize`); a change of text size
    redraws, since the render key is now theme and text size.
- **Diagram viewer (src/diagram-viewer.js, new).** On a shrunk or cut-off
  diagram a 28 × 28 button appears on hover (always on touch screens). It
  opens the diagram in a modal window: fitted to the window (at most its
  natural size), zoomed with the wheel or a pinch from 25 % to 400 %
  around the pointer, panned by dragging, `+`/`-` and the bar's buttons
  zoom, `0` or the percentage fits it again, `Esc` closes. In Edit mode the
  button opens the viewer and a click elsewhere on the diagram still opens
  its source.
- **Export (src/export.js).** Exports draw diagrams whole (`fit: false`),
  without the button.
- The page state the incremental render ignores includes the new class
  `diagram-reduced` (src/incremental-render.js).

## Limits

- The diagram button is reached with the mouse; there is no keyboard path
  to it yet.
- The diagram's layout width is taken when it is drawn; a later, narrower
  column shrinks it rather than laying it out again.
